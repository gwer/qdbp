# С чем не согласен

Ниже предложения аудита, которые не принимаю полностью или частично. Причины три: противоречат принятым решениям (CLAUDE.md, `docs/03-tech.md`), дают оверинжиниринг на текущем этапе или не подкреплены пользой.

## Не делать

| Пункт | Предложение аудита | Почему не согласен |
|---|---|---|
| F11 / U04 | При смене единиц всегда конвертировать значения, а не подставлять `defaultImperial` | Поведение намеренное (CLAUDE.md, docs/03-tech.md 6.5): если пользователь не трогал поле, американец видит «круглый» пример (160 lb, 69 in), а не 154,32 lb. Введённые вручную значения уже конвертируются. Редкий случай «ввёл вручную ровно дефолт» не стоит отдельной кнопки «Пример» и усложнения движка. |
| F12 | Предупреждение и блокировка экспорта QR при одинаковых цветах | Пользователь сам выбрал белое на белом и сразу видит пустой квадрат в превью. Ценность нулевая. |
| F15 | Подсказка «нужно минимум два варианта» в жребии | Кнопка неактивна, ситуация очевидна. |
| F16 | `noscript` и различение образца и расчёта без JS | Аудитория без JS ничтожна; пререндеренный результат — это осознанный образец для SEO. |
| C10 (часть) | Хранить численные примеры статей как структурированные данные и проверять тестами | Инфраструктура ради редких расхождений. Правило CLAUDE.md «цифры в примерах сверять с реальным расчётом» достаточно: проблема в соблюдении правила, а не в его отсутствии. Источники и дату проверки на финансовых и медицинских страницах добавлять по мере правки текстов, не отдельным проектом. |
| S03 | Пересмотреть длину title/description | Аудит сам пишет, что это не ошибки. Без данных о CTR смысла нет. |
| S07 | WebSite/CollectionPage/ItemList на главных и категориях | Польза не доказана, аудит сам ставит это в низкий приоритет. |
| U04 (часть) | Кнопки «Поделиться», «Сбросить», «Загрузить пример», CSV-экспорт таблиц | Новые функции без сигнала спроса. Адрес с расчётом уже можно скопировать из адресной строки. |
| U08 (часть) | Ручной переключатель темы | Сам аудит предлагает делать только при наличии запросов. |
| 06, «Метрики» | Событийная аналитика, система метрик качества, P1/P2 как критерий релиза | Для одного разработчика на этапе до трафика это лишнее. Хватает Cloudflare Web Analytics, поисковых панелей и `pnpm check`. |
| 06, этап 2 п. 6 | Матрица реальных браузеров: Firefox, Safari, Android, iPhone | Полный прогон дорогой. Достаточно разово открыть файловые инструменты и формы с датами на своём телефоне. |
| C11 (RU) | «Декодер JWT: посмотреть содержимое» вместо «расшифровка»; «Кодирование и декодирование URL» вместо «encode и decode» | Это стилистика против вероятных поисковых запросов («расшифровать jwt», «url encode/decode»; частотность не проверялась — вернуться по данным Search Console). Форма заголовков (существительное + уточнение) уже правильная. Предупреждение, что подпись не проверяется, на странице есть. |
| S06 | Проверить поведение URL на проде | Уже проверено (см. README): редиректы и 404 на qdbp.net корректны. |

## Частичное несогласие с формулировками

- **S01 и C01: «отдельная страница о приватности не нужна».** Для подвала это верно. Но по roadmap (фаза 4) privacy policy обязательна для AdSense и GDPR и всё равно появится перед монетизацией. Ссылку «Подробнее» в подвале тогда можно будет добавить. Противоречия с аудитом нет, просто аудит рассматривал только подвал.
- **S01: «страницы о проекте и контактах — до рекламы».** Согласен, это уже есть в фазе 4 roadmap. Делать раньше нет смысла.
- **Слаг `net-salary → russia-net-salary`.** Не согласен. Инструмент есть только в `ru`, другие страны не планируются. Если появятся, получат свои слаги (`uk-net-salary` и т. п.), а российский слаг можно будет не трогать. Ради гипотетического будущего не переименовываем.
- **Языковая вычитка 09 как готовый пакет.** Правки сделаны ИИ, их надо просматривать. Особенно медицинские формулировки и всё, где меняется смысл. Механическое применение всех 138 правок не принимаю.
