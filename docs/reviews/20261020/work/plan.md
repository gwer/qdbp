## Этап 1. Ошибки расчётов и потеря данных

Порядок внутри этапа — от простого к сложному, каждую ошибку отдельным коммитом.

- [x] **F03** `uniqueNames`: множество выданных имён, суффикс подбирается в цикле. Тест: `['a.jpg','a.jpg','a (2).jpg']` → три разных имени.
- [x] **F13** `stats.ts`: максимум частоты считать циклом. Тест на 150 000 значений.
- [x] **F08** `date.ts`: нормализованный модуль `((n % 7) + 7) % 7` во всех четырёх местах. Тесты: 27–29.12.1969 → 0 будних дней; 28.12.1969 → ISO-неделя 52 1969 года.
- [x] **F10** `parse.ts`: при нескольких разделителях принимать только корректную группировку по 3 цифры, иначе `null`. Тесты: `1.2.3`, `1,23,4` → ошибка; `1.234.567` (de), `1,234,567` (en) → число.
- [x] **F14** калории: `min: 18` у возраста, проверить тексты на всех языках.
- [x] **F05** дроби: арифметика на `BigInt`, проверка диапазона до перевода в `number`; убрать `-0` в десятичном выводе. Тест — пример из отчёта и `compute-checks.json → precision`.
- [x] **F07** `zonedToUtc`: явно определять gap и overlap для обоих знаков смещения. Политика для gap — сдвиг вперёд (как обещано в справке), для overlap — более раннее время. Тесты: Нью-Йорк и Берлин, весна и осень, зона с получасовым смещением.
- [x] **F06** возраст 29.02: одно правило (в невисокосный год день рождения — 28.02) для полного возраста и для «до дня рождения». Сверить с текстом статьи.
- [x] **F02** компрессор: если перекодированный файл не меньше исходного JPEG, отдавать исходник без метаданных — вырезать APP1/APP13/COM-сегменты без перекодирования, примерно 30 строк разбора маркеров. Для PNG/WebP — не обещать в тексте больше, чем делаем. Тест: JPEG с EXIF и COM на входе → на выходе их нет.

Итоги этапа 1:
- F02: использован готовый `stripJpeg` из удаления EXIF (перенесён в `src/ui/files/jpeg.ts` — понадобился второй раз). ICC и ориентация сохраняются. WebP, который не удалось уменьшить, возвращается как есть — так и написано в справке (5 языков). Проверка скачанного файла в браузере — в этапе 4.

- F06: выбрано правило «если в месяце нет нужного числа, месяц заканчивается в последний день» — как в `addMonths` и ст. 192 ГК. Следствие: 31.01 → 29.02 теперь ровно месяц (раньше 29 дней); справка возраста исправлена на 5 языках.

## Этап 6. Замечание повторной приёмки ([11-verification-stage-5.md](../11-verification-stage-5.md))

- [x] **V06**: заполняющие `FF` перед RST0–RST7 (`FF FF D0`, допустимо по T.81 §B.1.1.2) принимались за конец скана, и разбор ломался (`bad marker`). Поиск конца скана вынесен в `scanEnd`: сначала пропускаются все `FF`, потом проверяется код маркера; RST с заполнением остаются данными скана. Тест дополнен сканом с одним и двумя заполняющими `FF`.
- [x] Удаление EXIF: при добавлении файл теперь разбирается целиком, так что битый JPEG получает понятную ошибку «не удалось прочитать», а не исключение при рендере.

Проверка: `pnpm check` (704 теста); копия `recheck-v2-edges.mjs` проверяющего — 7/7 (было 4/7), пиксели файла с заполнением до и после очистки совпадают по SHA-256.
