# 02. План работ

Оценки времени — для одного разработчика, частично занятого (~15–20 ч/неделю), с активным использованием LLM для контента и переводов. При полной занятости делить примерно на 2.

## Фаза 0. Решения до кода (1 неделя)
- [x] Домен: **qdbp.net** — см. [08](08-risks.md#f-бренд-и-домен). Зарегистрировать (удобно через Cloudflare Registrar).
- [ ] Определить юрисдикцию владельца → какие рекламные сети доступны, нужен ли РСЯ, кто платит налоги.
- [ ] Утвердить стартовые языки (рекомендация: en, es, de, pt, ru — см. [05](05-languages.md)).
- [ ] Утвердить стартовые кластеры (рекомендация ниже).
- [ ] Завести Google Search Console, Bing Webmaster Tools, Яндекс Вебмастер (если ru).

Статус на 2026-10-19: основа сделана, см. отметки.

- [x] Layout, дизайн-токены, тёмная тема (по системной настройке), мобильная вёрстка, свой минимальный CSS.
- [x] i18n-слой: словари UI, роутинг `/{lang}/...`, hreflang, переключатель языка, строгие проверки переводов.
- [x] Модель инструмента + движок калькуляторов (см. [03](03-tech.md#5-модель-инструмента)).
- [~] SEO-база: мета-теги, canonical, hreflang, sitemap, JSON-LD (WebApplication, BreadcrumbList) — есть; статической OG-картинки пока нет.
- [x] Страницы: главная языка, хаб категории, инструмент, 404. Корень — 302 на `/en/`. Служебные страницы не делаем до фазы 4 (см. там).
- [x] `pnpm check` (типы, тесты, сборка, `urls.txt`, внутренние ссылки, бюджеты, отчёт покрытия).

- [x] Аналитика: Cloudflare Web Analytics включена (автоматическая вставка скрипта работает и для Workers).

**Критерий выхода:** 3 тестовых инструмента (простой калькулятор, калькулятор со своим блоком результата, свой компонент) на 5 языках ✅, `pnpm check` зелёный ✅, сборка < 30 с ✅ (~1 с), ручной Lighthouse ≥ 95 — проверить после деплоя.

## Фаза 2. MVP-контент (6–8 недель)
Статус: кластер «Даты и время» — 7 инструментов (возраст, дни между датами, прибавить к дате, прибавить/вычесть время, сколько времени между, номер недели, Unix timestamp); «Рабочие дни с праздниками» отложены — `date-holidays` весит ~11 МБ и требует атрибуции (CC-BY 3.0), нужен отдельный подход.
Цель — ~30 страниц P0 из [04](04-catalog.md) в 4 кластерах, глубоко, а не широко. Почти всё — сложность S/M.

Стартовые кластеры:
1. **Даты и время** (возраст, дни между датами, прибавить дни, сложение времени, неделя года, Unix time, рабочие дни с праздниками).
2. **Проценты и бытовая математика** (проценты всех видов, пропорция, среднее, случайные числа, системы счисления).
3. **Финансы** (наценка/маржа/скидка, НДС, чаевые, кредит с графиком платежей, вклад/сложный процент, ипотека).
4. **Ремонт и строительство** (краска, ламинат, бетон, кирпич, обои, плитка) — высокий RPM, слабая конкуренция в ru/de/pl/es.

Изображения — первый кластер фазы 3: инструмент тянет файловую инфраструктуру (L), но даёт трафик и ссылки.

- [ ] Каждый инструмент: работающий UI, текст «как пользоваться / как считается / примеры / FAQ», 3–6 ссылок на связанные инструменты.
- [ ] Переводы на стартовые языки с глоссарием, вычитка носителем хотя бы топ-20 страниц.
- [ ] Отправка sitemap, проверка индексации.

**Критерий выхода:** всё проиндексировано, нет ошибок Core Web Vitals в GSC.

## Фаза 3. Рост наполнения (месяцы 3–12)
- Темп: **3–5 новых инструментов в неделю**; сначала дешёвые ★★★ («быстрые победы» в [04](04-catalog.md#итог)), сложные — только однозначно ценные.
- Новые кластеры по приоритетам из [04](04-catalog.md): изображения → текст и кодирование (почти всё S) → здоровье → кухня → конвертеры единиц → PDF → dev-утилиты → локальные валидаторы (вместе с открытием соответствующих языков).
- Добавление языков волнами (см. [05](05-languages.md)), только для инструментов, у которых есть подтверждённые показы в GSC на основных языках.
- Ежемесячно: разбор GSC (какие запросы дают показы без кликов → улучшить title/контент; какие страницы не индексируются → углубить или убрать).
- Продвижение по плану [06](06-promotion.md).

## Фаза 4. Монетизация (с ~10–30 тыс. визитов/мес)
- [ ] До подачи в AdSense: страница «Конфиденциальность и контакты» на всех языках (privacy policy обязательна по правилам AdSense и GDPR; контакт снижает риск отказа). Email — через Cloudflare Email Routing (например, hello@qdbp.net). About и terms — не обязательны.
- [ ] Подключить CMP (Google-сертифицированная, IAB TCF v2.2) для EEA/UK/CH.
- [ ] AdSense как старт → при росте Journey by Mediavine / Ezoic → Raptive/Mediavine при выходе на их пороги.
- [ ] Резервирование мест под рекламу (нулевой CLS), ленивая загрузка рекламного скрипта.
- [ ] A/B размещения рекламы: не больше 2–3 блоков на инструмент, никогда не между полями ввода и результатом.
- [ ] Для RU-трафика — РСЯ (если юрисдикция позволяет).

## Фаза 5. Масштаб (год 2+)
- Дальнейшее расширение языков и кластеров.
- Встраиваемые виджеты калькуляторов для чужих сайтов (с обратной ссылкой) — масштабируемый линкбилдинг.
- PWA/оффлайн для популярных инструментов.
- Поиск по сайту (когда инструментов 150+): предсобранный индекс на язык, клиентский поиск.
- Возможные доп. доходы: affiliate (финансы, стройка), донаты, платная версия без рекламы (потребует бэкенда для лицензий — отложить).

## Постоянные практики
- Каждый инструмент покрыт юнит-тестами формулы (эталонные значения из независимых источников).
- Каждая страница проходит чек-лист качества перед публикацией (см. [03](03-tech.md#12-чек-лист-публикации-инструмента)).
- Отказ от публикации «тонких» страниц: если нечего сказать сверх формулы, страница не создаётся или объединяется с соседней.
