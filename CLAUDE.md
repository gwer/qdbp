# qdbp.net — инструкции для агента

Статический мультиязычный сайт браузерных инструментов и калькуляторов. Монетизация — реклама, трафик — SEO.
Общаемся на русском. Исходный контент инструментов пишется на русском.

## С чего начать сессию
- `docs/README.md` — карта документов и главные выводы; `docs/02-roadmap.md` — что сделано и что дальше (отметки по фазам).
- `docs/03-tech.md` — архитектура и принятые решения (раздел 13 — что сознательно НЕ делаем). Перед архитектурными изменениями сверяться с ним, после — обновлять.
- `docs/04-catalog.md` — какие инструменты делать и в каком порядке (ценность × сложность).
- Документы — живые черновики для обсуждения: решения в них меняются по итогам разговора, правь их, когда решение изменилось.

## Команды
- `pnpm dev` / `pnpm build` / `pnpm test`
- `pnpm check` — типы, тесты, сборка, пост-проверки `dist/`. Должен быть зелёным, прежде чем говорить «готово».
- `pnpm urls:update` — подтвердить изменения списка URL в `urls.txt` (только когда появление/удаление страниц намеренное).

## Структура (подробно — docs/03-tech.md, разделы 3–5)
- `src/pages/[lang]/{category}/{tool}/` — папка = URL. `index.astro` — одинаковый у всех инструментов (копировать как есть); всё своё — в `_tool/`: `tool.ts` (`export const def = defineCalculator|defineTool(...)`, `export default island(def)`), тесты, код, `i18n/{lang}.json`, `content/{lang}.md`.
- `src/pages/[lang]/{category}/` — `index.astro` (одинаковый у всех категорий) + `_category/` (`category.ts`, `i18n/{lang}.json`).
- Общая обвязка страниц — `src/layouts/ToolPage.astro`, `CategoryPage.astro`, `Base.astro`. Каталог и все проверки файлов — `src/lib/catalog.ts`, `src/lib/validate.ts`.
- Языки сайта — `src/i18n/config.ts` (`SITE_LANGS`); общие строки — `src/i18n/ui/{lang}.json`.

## Правила, которые легко нарушить
- Только клиентская логика, никакого сервера. Без инструментов на часто меняющихся данных (курсы, ставки «на сегодня»): такое значение — поле ввода.
- Язык у инструмента включён, если есть и `i18n/{lang}.json`, и `content/{lang}.md`. Наборы ключей во всех языках одного инструмента одинаковые.
- Слаги английские на всех языках; URL после публикации не меняются без редиректа в `public/_redirects`.
- Числа: поля `type="text"`, разбор — `parseNumber(input, lang)`, вывод — только через `src/lib/format.ts`. Деньги — `decimal.js-light`. Ничего, зависящего от «сегодня», при сборке не считать (сборка в UTC).
- Если отрицательные значения не нужны — ставить `min: 0` (это и проверка, и цифровая клавиатура на телефоне).
- Формулы — тесты с эталонами из независимого источника. Цифры в примерах `content/*.md` сверять с реальным расчётом.
- Переводы: не дословно, а с адаптацией (местная валюта, реалии, термины рынка — Price/SAC в pt, sistema francés в es и т. п.).
- Предпочитать стандартные механизмы Astro/Preact своим, даже ценой небольшого шаблонного кода. Минимум абстракций: новое общее — только когда понадобилось второй-третий раз.
- Версии зависимостей — выпущенные не меньше двух недель назад.

## Проверка изменений в UI
Юнит-тестов для интерфейса нет. После изменений в UI — проверить в браузере: в системе есть `/usr/bin/google-chrome`; `playwright-core` ставить во временную папку (scratchpad), не в проект. Сайт локально — `pnpm build && pnpm preview` (порт 4321; preview запускается как демон, останавливать `pnpm exec astro preview stop`).

## Работа с пользователем
- Коммитить только по просьбе пользователя.
- Если просят «объясни» или «ничего не меняй» — сначала объяснение, без правок.
- Пользователь чувствителен к оверинжинирингу: предлагать минимальное решение, всё «на будущее» явно откладывать.
- Рекомендации — с проверкой фактами (замер, сборка, документация), а не по памяти; если не проверено — так и сказать.
